# ds-ops/map — карта использования компонентов дизайн-системы

Три подсчёта, все по `medusa-src/packages/admin/dashboard/src/`:

- `components.json` — системный слой, компоненты из
  `medusa-src/packages/design-system/ui/src/components/`.
- `local-components.json` — локальный слой, компоненты из
  `dashboard/src/components/`.
- `screens-products.json` — разрез по экранам раздела
  `dashboard/src/routes/products/`: что импортирует каждый экран
  из обоих слоёв. Метод описан внутри файла, в поле `method`.

Данные на 2026-08-28. Только подсчёт, без оценок.

## Что считали

**Источник компонентов** — 46 директорий в `ui/src/components/`.

**Соответствие «имя в коде → компонент»** берётся из `ui/src/index.ts`.
Например `export { Checkbox, type CheckboxCheckedState } from "./components/checkbox"`
(`index.ts:7`) означает, что оба имени относятся к компоненту `checkbox`.

**Импорт** — вхождение имени в списке `import { ... } from "@medusajs/ui"`
внутри `dashboard/src`, а не вхождение имени в тексте файла.

- `imports` — сколько раз имя встретилось в таких списках.
- `files` — из скольких разных файлов. Числа расходятся, только если
  один файл импортирует одно имя несколькими инструкциями.
- У компонента с несколькими экспортами числа суммируются по всем его
  именам; разбивка сохранена в `per_symbol`.

## Как считали

Обход `dashboard/src` по `.ts` и `.tsx`, регулярное выражение по
инструкциям импорта из `@medusajs/ui`. Из текста предварительно вырезаны
комментарии — закомментированные импорты и закомментированные строки
внутри многострочных списков не учитываются.

Сверка: `grep -r 'from "@medusajs/ui"'` даёт 568 строк в 567 файлах.
Разница в два — те самые закомментированные импорты.

`date-segment` и `time-input` не экспортируются из `ui/src/index.ts`,
поэтому их ноль получен по построению: импортировать их из
`@medusajs/ui` нельзя. Они вынесены в поле `no_public_export_from_index`.

## Чего этот способ подсчёта не видит

**Частоту использования в разметке.** Один импорт на файл — это один
импорт, сколько бы раз компонент ни встречался в JSX этого файла.

**Косвенное использование.** Компонент, который применяется внутри
другого компонента дизайн-системы, здесь не отражён.

**Локальные одноимённые компоненты.** Имя может использоваться в
дашборде и при нулевом импорте из `@medusajs/ui`. Пример: `Skeleton`
даёт 0 импортов из пакета, при этом имя встречается в `dashboard/src`
170 раз — из собственного `components/common/skeleton`.

**Другие потребители.** Считался только `dashboard/src`. Импорты из
`@medusajs/ui` в других пакетах монорепо, в `store/` и в тестах и
сторибуках самого `ui` не учитывались.

**Динамические и звёздочные импорты.** `import * as` и `import()` не
считаются. В `dashboard/src` таких обращений к `@medusajs/ui` не нашлось,
как и ре-экспортов `export { ... } from "@medusajs/ui"` — оба счётчика
нулевые (`star_imports`, `reexport_files` в JSON).

**Не-компонентные экспорты.** `clx`, `toast`, `usePrompt`,
`useDataTable`, блок `DataTable*` и типы из `export * from "./types"`
(`index.ts:48-59`) к компонентам не привязаны, они собраны отдельно в
`non_component_symbols_imported`.

## Воспроизведение

Скрипт разовый, в репозитории не сохранён. Метод описан выше целиком:
карта имён из `ui/src/index.ts`, обход `dashboard/src`, регулярное
выражение по `import { ... } from "@medusajs/ui"` после вырезания
комментариев.

# Локальный слой — `local-components.json`

Компоненты из `dashboard/src/components/`: из скольких файлов
`dashboard/src` импортируется каждый.

## Что считали

**Компонент** — директория под `src/components/`, у которой есть
`index.ts`. Таких 126 из 157 директорий всего.

**Алиасы путей.** В `dashboard/tsconfig.json` нет `compilerOptions.paths`,
в Vite-конфигах `resolve.alias` тоже не задан. Все импорты внутри
дашборда относительные, так что учитывать было нечего.

**Привязка импорта.** Относительный путь разрешается от файла-импортёра,
и импорт засчитывается ближайшей вышестоящей директории с `index.ts`.
Импорт `../../common/skeleton/skeleton` попадает в `common/skeleton`.

Дополнительно к первому подсчёту учитываются динамические `import()`.
Ре-экспорты `export ... from` в счёт импортов не идут, они вынесены
в поле `reexports`.

## Пересечение с @medusajs/ui

Один случай — `skeleton`:

| | путь | файлов | импортов |
|---|---|---:|---:|
| локальный | `dashboard/src/components/common/skeleton` | 45 | 45 |
| системный | `ui/src/components/skeleton` | 0 | 0 |

Проверено двумя способами независимо: по имени директории и по
экспортируемому имени, прослеживая `export * from` в файлы реализации.
Оба дают ровно один этот случай.

## Чем этот подсчёт отличается от первого

**Единица счёта.** В первом подсчёте единица — имя, импортируемое из
одной плоской бочки `@medusajs/ui`. Здесь единица — путь к модулю,
разрешённый в директорию. Поэтому там числа привязаны к символам,
здесь — к директориям.

**Бочки поглощают вложенное.** Правило «ближайшая вышестоящая директория
с `index.ts`» означает, что импорт через родительскую бочку засчитывается
родителю, а не вложенному компоненту. `modals` набирает 270 файлов, а
вложенный `modals/route-drawer` — ноль, хотя импортируется через
`components/modals` (`components/modals/index.ts:1` его ре-экспортирует).
В первом подсчёте такого эффекта нет: у `@medusajs/ui` один уровень.

**Ноль значит разное.** Там ноль означал, что имя ни разу не импортируется
из пакета. Здесь ноль может означать и это, и то, что компонент берут
через бочку выше. Из 15 нулей часть — второго рода.

**`imports` и `files` расходятся чаще.** В первом подсчёте они совпали у
всех компонентов. Здесь один файл может обращаться к одной директории
несколькими инструкциями: у `layout-composer` 94 импорта из 80 файлов,
у `data-grid` — 54 из 49.

**Считаются импорты из самого компонента.** Файл внутри директории
компонента, импортирующий соседний файл этой же директории, попадает
в счёт. Для сравнения рядом лежит поле `files_outside_own_dir`.

**Директории без `index.ts` не считаются вовсе.** 10 импортов ведут
в четыре такие директории — `common/sidebar-link`, `common/tax-badge`,
`table/table-cells/common/tiered-price-cell`,
`table/table-cells/customer/account-cell`. Они перечислены в поле
`imports_into_dirs_without_index`.

**Динамические импорты.** Здесь `import()` учитывается; в
`dashboard/src` их 224 суммарно по всем адресатам. В первом подсчёте
динамических обращений к `@medusajs/ui` не было вовсе.

**Что общее.** Тот же набор просмотренных файлов (1939), то же вырезание
комментариев, тот же принцип: считаются импорты, а не вхождения имени
в текст.

## Чего этот подсчёт не видит

Всё из списка для первого подсчёта, кроме пункта про других
потребителей: здесь потребитель и источник — один и тот же пакет.
Дополнительно не видно, какая доля из 270 импортов `modals` приходится
на каждый вложенный компонент бочки.
