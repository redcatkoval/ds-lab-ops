# DEC-012. Плоский список упраздняет группировку вместе с role="group"

**Решили.** Переход `ActionMenu` на плоский список действий упраздняет
группы. Вместе с ними из разметки исчезает элемент `role="group"`.
Потерю принимаем.

**Основание для упразднения групп.** Отдельного решения о плоском
списке в `ds-ops/decisions/` нет — проверено, DEC-001…DEC-011 такого
не содержат. Решение принято при записи контракта и живёт там:
`ds-ops/contracts/action-menu.md`, раздел 3, «**Решение.** Плоский
список действий вместо групп». Этим решением DEC-012 и опирается.

Причина по существу: меню из N действий должно объявляться как меню
из N действий, а не как N групп по одному действию. Сейчас в продукте
преобладает именно вырожденный случай — из 110 вызовов с литеральным
списком 41 передаёт две группы и 14 три, и почти во всех группа
содержит одно действие. Группа перестала быть группой.

**Почему потеря допустима.** После правила 4.2 (коммит `ebfeb35a`)
разделитель ставится между всеми действиями, а не между группами.
С этого момента группа не даёт ни одного видимого следствия: ни
отступа, ни заголовка, ни разделителя, которого не было бы и так.
Она осталась только в дереве доступности.

## Что измерено

Отрисовал одно и то же меню из трёх действий в двух формах — тремя
группами по одному и одной группой из трёх — и сравнил разметку
и поведение с клавиатуры. jsdom, Radix через `@medusajs/ui`.

| | 3 группы по 1 | 1 группа из 3 |
|---|---|---|
| элементов `role="group"` | 3 | 1 |
| атрибуты у группы | только `role="group"` | только `role="group"` |
| атрибуты элемента `role="menu"` | совпадают | совпадают |
| пунктов `role="menuitem"` | 3 | 3 |
| атрибуты каждого пункта | совпадают | совпадают |
| разделителей | 2 | 2 |
| `ArrowDown` ×4 | Ред. → Права → Удалить → Удалить | то же |
| `Home` | Редактировать | Редактировать |
| `End` | Удалить | Удалить |
| поиск по букве «У» | Удалить | Удалить |

**Ничего, кроме числа обёрток `role="group"`, не отличается.**

- **Навигация с клавиатуры не задета.** Порядок обхода стрелками,
  `Home`, `End` и поиск по первой букве работают одинаково. Роверинг
  фокуса Radix держит на `[data-radix-collection-item]` внутри
  `role="menu"`, а не на группах.
- **Объявление пунктов не задето.** У `menuitem` совпадает всё, вплоть
  до `tabindex` и `data-orientation`. Ни `aria-posinset`, ни
  `aria-setsize` Radix не выставляет ни в одной из форм, так что
  «пункт 2 из 3» скринридер не произносил и раньше.
- **Группа была безымянной.** У элемента `role="group"` нет ни
  `aria-label`, ни `aria-labelledby` — компонент их никогда не задавал.
  Безымянная группа сообщает границу, но не сообщает, чем эта группа
  является. Мы теряем разделение без названия, а не осмысленную
  рубрикацию.

## Отвергнутая альтернатива

Сохранить группы ради дерева доступности и снабдить каждую
`aria-label`. Отвергнуто: названия групп в продукте не существуют —
их пришлось бы придумать на 55 вызовов, и это была бы правка смысла,
а не формы. Контракт таких названий не вводит.

## Границы

Решение относится к `ActionMenu` в `dashboard/src/components/common/`.
Оно не высказывается о меню на `DataTableAction`
([Q-014](../questions/Q-014-dva-tipa-deystviy.md)) и о копии
компонента в плагине
([Q-015](../questions/Q-015-kopiya-komponenta-v-plagine.md)) —
там группировка живёт своей жизнью.

**Побочное следствие, о котором стоит знать.** Потеря начинается
не с плоского списка, а раньше. Шаг 0 (коммит `c05fe3e4`) уже свёл
пять вызовов из нескольких групп в одну, и число `role="group"`
на этих экранах уже уменьшилось. Плоский список доведёт его до нуля.
