# DEC-011. Опасное действие в меню окрашивается токеном fg-error

**Решили.** Разрушающее действие внутри `ActionMenu` окрашивается
токеном `--fg-error` — классом `text-ui-fg-error`. Не `button-danger`,
не палитрой Tailwind, не литералом.

**Основание.** Измерение `ds-ops/tokens/red-usage.json`, 2026-09-02.

1. **Прецедент в продукте.** Пункт меню удаления уже окрашен этим
   токеном: `view-pills.tsx:227-235` — `DropdownMenu.Item` с классом
   `text-ui-fg-error`, иконка `Trash` без своего класса. Решение не
   вводит новое, а закрепляет то, что в продукте уже выбрано один раз.
2. **`fg-error` — токен переднего плана.** 9 употреблений из 17, все
   в контексте «текст». В Tailwind разложен как `text-ui-fg-error`
   (`ui-preset/src/theme/extension/theme.ts:289`).
3. **`button-danger` — токен заливки.** Все 3 употребления —
   `button.tsx:37-39`, все три в контексте «фон»
   (`bg-ui-button-danger`, `hover:`, `active:`). Вне кнопки не
   употребляется ни разу.

**Отвергнутая альтернатива — `button-danger`.** Отвергнут по назначению:
это цвет заливки кнопки, а не цвет текста. Пункт меню — строка текста
с иконкой, заливки у неё нет. Взять `button-danger` на текст значит
употребить токен не в той роли, в которой он употребляется во всех трёх
существующих местах.

**Наблюдение, из-за которого решение вообще понадобилось.** В продукте
сейчас три разных решения для одного и того же — «удалить»:

| место | как окрашено |
|---|---|
| `view-pills.tsx:227-235` | пункт меню, `text-ui-fg-error` — красный текст |
| `metadata-form.tsx:250-256` | пункт меню, `Trash` с `text-ui-fg-subtle` — красного нет |
| `product-media-gallery.tsx:131-140` | `IconButton` без `variant` — красного нет |

Все три — удаление. Три разных вида. Контракт устраняет разнобой
для случая меню; два других случая — вне его границы.

**Границы решения.**

Решение относится к пункту `ActionMenu` и только к нему. Оно не
высказывается о том:

- как окрашивать удаление кнопкой (`Button`, `IconButton`);
- как окрашивать подтверждение в `Prompt` — там кнопка, и вариант
  `danger` стоит по умолчанию (`prompt.tsx:43`, `prompt.tsx:142`);
- нужен ли красный там, где его сейчас нет.

**Связь с контрактом.** Правило 4.3 контракта `ActionMenu`
(`ds-ops/contracts/action-menu.md`) требует, чтобы разрушающее действие
было помечено красным, но линтером не проверяется: признака
`destructive` в типе `Action` нет (`action-menu.tsx:9-26`). DEC-011
называет, каким именно красным, — то есть задаёт, что должна будет
проверять реализация правила. Само по себе решение компонент не меняет.

**Открытый вопрос рядом.** `fg-error` и `button-danger` неразличимы
в светлой теме и контрастны в тёмной — `ds-ops/questions/Q-013`.
На выбор токена это не влияет: выбор сделан по роли, а не по значению.
