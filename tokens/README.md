# ds-ops/tokens — слой токенов дизайн-системы

Два измерения:

- `tokens.json` — слой токенов пакета
  `medusa-src/packages/design-system/ui-preset`.
- `literals.json` — литеральные значения в компонентах: цвета мимо
  токенов и размерные утилиты числом. Метод описан внутри файла,
  в поле `method`; краткая сводка — в конце этого README.

Данные на 2026-08-28. Только измерение.

## Генератор найден

Файлы в `theme/tokens/` и `theme/extension/theme.ts` не пишутся руками.
Их производит команда `toolbox tokens -o './src/theme'`
(`ui-preset/package.json:29`), реализация —
`packages/design-system/toolbox/src/commands/tokens/command.ts`.

Источник данных — файл Figma, забираемый по HTTP API: идентификатор
файла в `toolbox/src/constants.ts`, доступ по `FIGMA_TOKEN`
(`ui-preset/.env.template`). Отсюда и случайный порядок ключей: он
повторяет порядок узлов в ответе Figma.

Генератор пишет пять файлов: `tokens/colors.ts` (`command.ts:303`),
`tokens/effects.ts` (`:320`), `tokens/components.ts` (`:336`),
`tokens/typography.ts` (`:179`) и `extension/theme.ts` (`:441`).

`theme.ts` строится из **светлой** темы: по ключам `colors.light`
(`command.ts:360`) и `effects.light` (`:424`). Тёмная тема на состав
`theme.ts` не влияет.

## Что считали

**Токен** — CSS-переменная, объявляемая в `tokens/colors.ts` или
`tokens/effects.ts`. Классы типографики и компонентные классы
переменными не являются и в счёт токенов не входят, они посчитаны
отдельно.

**Слой** определялся по тому, как токен задан: значение-литерал —
примитив, значение со ссылкой `var(--другой-токен)` — семантика.

**Имя класса Tailwind** взято из разобранного `theme.ts`, а не выведено
из имени переменной. Цвета попадают в `theme.extend.colors.ui`, тени —
в `theme.extend.boxShadow`.

## Что есть и чего нет

`theme.extend` из `theme.ts` содержит ровно два ключа: `colors` и
`boxShadow`. Плагин добавляет к ним `fontFamily`, `transitionProperty`,
`keyframes` и `animation` (`plugin.ts:42-67`).

Отступов, радиусов и размеров в пакете нет: ключей `spacing`,
`borderRadius`, `fontSize`, `borderWidth`, `screens`, `zIndex` в
исходниках `ui-preset/src` не встречается. Слой покрывает цвет, тени и
типографику.

Типографика задана не переменными, а готовыми CSS-классами: генератор
собирает их из текстовых стилей Figma (`command.ts:104-177`), плагин
подключает через `addComponents` (`plugin.ts:21`). У каждого класса
четыре свойства: `fontSize`, `lineHeight`, `fontWeight`, `fontFamily`.

`tokens/components.ts` пуст: `{"dark": {}, "light": {}}`. Генератор
кладёт туда классы линейных градиентов (`command.ts:245`); в текущей
выгрузке градиентов нет.

## Темы и переключение

Тем две: `light` и `dark`.

Переключение — `plugin.ts:28-39`. Если в конфиге Tailwind
`darkMode: "class"`, тёмные значения объявляются под классом (по
умолчанию `.dark`). Иначе — под `@media (prefers-color-scheme: dark)`.
Потребитель задаёт `darkMode: "class"`
(`dashboard/tailwind.config.cjs:14`), то есть работает первая ветка.

Ветки не симметричны: в ветке с классом применяются только
`colors.dark` и `effects.dark` (`plugin.ts:30`), а `components.dark`
применяется лишь в ветке с media-запросом (`plugin.ts:36`). Сейчас
`components` пуст, поэтому разницы в выводе нет.

## Чего этот способ не видит

**Использование.** Считались объявления, а не обращения. Сколько раз
каждый токен применён в компонентах, здесь не измерялось.

**Соответствие Figma.** Проверялось содержимое файлов в репозитории.
Совпадают ли они с текущим состоянием файла Figma — неизвестно:
для этого нужен запуск генератора с `FIGMA_TOKEN`.

**Значения внутри теней.** Тень записана одной строкой; сколько в ней
слоёв и какие цвета внутри, не разбиралось.

**Цветовые утилиты.** Для цвета зафиксировано имя Tailwind
(`ui-bg-base`) и один пример класса (`bg-ui-bg-base`). Какие именно
утилиты с ним применяются в коде — `bg-`, `text-`, `border-` — не
проверялось.

**Классы вне двух файлов.** Компоненты `ui` могут объявлять собственные
CSS-переменные помимо `ui-preset`; такие объявления не искались.

**Другие потребители пресета.** Смотрели только `ui-preset` и настройку
`darkMode` в дашборде.

# Литералы в компонентах — `literals.json`

Считались три области: `ui/src/components/` (системный слой),
`dashboard/src/components/` (локальный), и
`routes/products/product-detail/` (срез). Для каждого литерала записаны
файл, строка, значение и тип.

В `.ts` и `.tsx` поиск идёт только внутри строковых литералов, в `.css`
— по всему файлу; комментарии вырезаны. Совпадения, начинающиеся с `ui-`
или содержащие `-ui-`, не считаются: это классы дизайн-системы.

## Отдельно про селекторы-варианты

`data-[state=open]`, `aria-[...]`, `has-[...]`, `group-data-[...]` —
это квадратные скобки условия, а не значения. Они вынесены в свой тип
и в число произвольных значений не входят. Первый прогон считал их
вместе, отчего произвольных было 435 вместо 305.

## Чего этот способ не видит

**Классы, собранные из кусков.** Если класс склеивается в рантайме
(`` `p-${n}` ``), он не совпадёт ни с одним шаблоном.

**Литералы вне строк.** Числа в JS-выражениях — размеры в пикселях,
переданные пропом или посчитанные, — не ищутся.

**Литералы за пределами трёх областей.** Экраны кроме нашего среза,
другие пакеты монорепо, `store/` не смотрели.

**Оправданность.** Считались вхождения. Отличить вынужденный литерал от
случайного этот способ не может.
