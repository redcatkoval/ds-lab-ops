## 1. Назначение

ActionMenu — меню действий над одной сущностью, свёрнутое под один
триггер. Раскрывается по нажатию, содержит плоский список действий,
каждое из которых либо ведёт по ссылке, либо вызывает обработчик.

Применяется в заголовке секции, в строке таблицы и в карточке — там, где
у сущности есть несколько действий и все они не помещаются в интерфейс
кнопками.

Наблюдение: используется в 104 файлах, 115 вхождений тега.

## 2. Когда не использовать

**Решение.** При одном действии ActionMenu не применяется. Нужна
иконочная или текстовая кнопка.

Одно действие под меню — это два клика вместо одного.

Наблюдение: сейчас так в 45 вызовах из 105 разобранных.
Ещё 1 вызов передаёт пустой список —
`routes/products/product-create/components/product-create-details-form/components/product-create-details-media-section/product-create-details-media-section.tsx:303`.

## 3. API

**Решение.** Плоский список действий вместо групп.

```ts
type Action = {
  icon: ReactNode
  label: string
  disabled?: boolean
  disabledTooltip?: string | ReactNode
  destructive?: boolean
} & (
  | { to: string; onClick?: never }
  | { onClick: () => void; to?: never }
)

type ActionMenuProps = PropsWithChildren<{
  actions: Action[]
}>
```

Изменения относительно текущего типа (`action-menu.tsx:9-35`):

| было | стало |
|---|---|
| `groups: ActionGroup[]` (`:33`) | `actions: Action[]` |
| тип `ActionGroup` (`:28-30`) | удалён |
| — | `destructive?: boolean` |
| `variant?: "transparent" \| "primary"` (`:34`) | удалён |

**Решение.** `variant` у триггера не используется.

`children` остаётся без изменений. Наблюдение: передан один раз —
`routes/orders/order-detail/components/order-summary-section/order-summary-section.tsx:212`,
подставляет `Button` вместо `IconButton` по умолчанию.

Имя `actions` для поля выбрано при записи контракта; в разговоре
решение звучало как «плоский список действий».

Поля `icon`, `label`, `disabled`, `disabledTooltip` и взаимоисключающая
пара `to` / `onClick` сохраняются как есть (`action-menu.tsx:9-26`).

## 4. Правила

Правила двух видов, и оба обязательны.
**[проверяется линтером]** — линтер находит нарушение сам и блокирует
мерж. **[проверяется человеком]** — правило обязательно ровно так же,
но статически не ловится, поэтому его проверяют на ревью.
Отдельно помечена одна **[рекомендация]** — она необязательна.

### 4.1 Число действий

**Решение.** Действий два или больше. Ноль и одно запрещены. **[проверяется линтером]**

**Решение.** До пяти действий. **[рекомендация]**

Это единственная рекомендация в контракте. Превышение не ошибка:
ни линтер, ни ревью его не блокируют. Больше пяти — повод пересмотреть
состав меню.

Правило о двух действиях линтер проверяет только там, где список задан
литералом. Наблюдение: из 115 вхождений список собирается в рантайме
в 10 (перечислены в фактах, раздел «Чего этот способ не видит»).
Эти 10 остаются на ревью.

### 4.2 Разделители

**Решение.** Разделитель ставится между всеми действиями. Группировки
нет. **[проверяется линтером]**

Разделитель — свойство компонента, не вызова. В API поля для него нет.

Наблюдение: сейчас разделитель ставится между группами
(`action-menu.tsx:118`), группы задаёт вызов. По 105 разобранным
вхождениям это 68 разделителей; по правилу их будет 85.

### 4.3 Разрушающее действие

**Решение.** Действие с `destructive: true` всегда последнее в списке.
**[проверяется линтером]**

**Решение.** Разрушающее действие помечено красным. **[проверяется линтером]**

Цвет задаёт компонент по признаку `destructive`, не вызов.

**Решение.** Разрушающее действие вызывает подтверждение.
**[проверяется человеком]**

Статической проверкой не покрывается: наличие подтверждения внутри
обработчика по типу не выражено. См. раздел 7.

### 4.4 Остальные действия

**Решение.** Действие, не помеченное `destructive`, либо открывает
шторку, либо переходит по ссылке. **[проверяется человеком]**

Переход по ссылке проверяется по наличию `to`. Открытие шторки внутри
`onClick` статической проверкой не отличается от любого другого
обработчика.

Наблюдение: из 189 действий в разобранных вхождениях 100 задают `to`,
89 — `onClick`. Действий без того и другого нет.

### 4.5 Триггер

**Решение.** Триггер без рамки. **[проверяется линтером]**

Проверяется отсутствием у компонента props, управляющих видом триггера.
После удаления `variant` вариант с рамкой выразить нечем.

Наблюдение: сейчас умолчание — `IconButton` с `variant="transparent"`
(`action-menu.tsx:39`, `:44`).

## 5. Токены

**Отступы** — по DEC-007 (`ds-ops/decisions/DEC-007-shkala-devyat-znacheniy.md`):
девять значений 2, 4, 6, 8, 12, 16, 24, 32, 64 px. Произвольные значения
в скобках не используются.

Наблюдение: в компоненте один класс отступа, `gap-x-2`
(`action-menu.tsx:85`, `:102`) — 8 px, шаг 2. В шкале DEC-007 есть.

**Радиусы** — по DEC-008 (`ds-ops/decisions/DEC-008-radiusy-pyat-znacheniy.md`):
пять значений 2, 4, 6, 8, 12 px плюс `full`, только именованными
ступенями.

Наблюдение: в компоненте радиусов нет ни одного.

**Цвет.** Наблюдение: литеральных цветов в компоненте нет. Цвет задан
токенами `text-ui-fg-subtle` (`:85`, `:102`) и `text-ui-fg-disabled`
(`:87`, `:104`).

Красный цвет разрушающего действия (правило 4.3) берётся из токенов
дизайн-системы. Конкретный токен в этом контракте не назначен.

## 7. Открытые зависимости

**7.1 Формулировка про триггер.** Правило 4.5 записано как «без рамки».
Точная формулировка зависит от контракта на кнопку, которого пока нет.
До него правило 4.5 читать как запрет на выбор вида триггера из вызова,
а не как описание вида.

**7.2 Подтверждение у разрушающих действий.** Не проверено поштучно,
есть ли подтверждение у всех 70.

Пофайловый признак (наличие вызова `prompt(` в файле вызова) даёт:
47 из 70 — в файле есть `prompt(`; 22 — обработчик есть, `prompt(` в
файле нет; 1 — не обработчик, а ссылка `to`.

Признак пофайловый, не по действию: файл может вызывать `prompt(` для
одного действия и не вызывать для другого. Поштучная проверка требует
разбора обработчиков и не проведена.

**7.3 Токен красного цвета** для правила 4.3 не назначен.
