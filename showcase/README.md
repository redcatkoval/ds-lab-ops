# ds-ops/showcase — витрина ActionMenu

Storybook по контракту `ds-ops/contracts/action-menu.md`, раздел 4.
Показывает и то, как должно быть, и то, как нельзя.

## Запуск

Из `ds-ops/`:

```bash
./showcase/run.sh
```

Открывается на `http://localhost:6006`.

## Намеренные нарушения

**Читать перед тем, как расширять область линтера.**

Две истории в `stories/action-menu-forbidden.stories.tsx` — это вызовы
`ActionMenu` с нулём и с одним действием. Они нарушают правило 4.1
контракта намеренно: витрина обязана показывать запрещённое состояние.

Линтер их сейчас не видит: область сканирования задана в
`tools/lint/rules/action-menu.json`, поле `scan.root`, и указывает
на `dashboard/src`. Истории лежат в `ds-ops/`.

Если область когда-нибудь расширят на `ds-ops/`, эти истории начнут
считаться нарушениями. Тогда `showcase/stories/` нужно внести
в `scan.exclude_paths` — иначе витрина нарушений сама станет нарушением.

То же касается вызова с `variant`, если такая история появится:
правило 4.5 её поймает.

## Где это живёт и почему снаружи

`medusa-src/` не изменяется. Конфиг, истории, кэш и symlink на
зависимости лежат здесь; Storybook зовётся с флагом `-c`.

Тот же приём, что в `ds-ops/dev/` — там так запускается сама админка.
Критерий тот же: `git status --short` в `medusa-src/` остаётся пустым.

Свой Storybook в монорепо есть, но он не подходит:
`medusa-src/packages/design-system/ui/.storybook/main.ts` собирает
истории только из `ui/src/**`, а `ActionMenu` живёт в дашборде —
`dashboard/src/components/common/action-menu/`. Чтобы витрина увидела
его оттуда, пришлось бы править чужой конфиг и смешивать дизайн-систему
с локальным компонентом её потребителя.

**Порт 6006 общий** с витриной пакета `ui` (`ui/package.json:11`).
Одновременно они не поднимутся.

**Ставить ничего не нужно.** `storybook@10.5.6`, `@storybook/react-vite`,
`@storybook/addon-themes`, `vite`, `tailwindcss` и `autoprefixer` уже
лежат в `medusa-src/node_modules`. Сюда они приходят через symlink
`showcase/node_modules`, как в `ds-ops/dev/`.

## Три места, где пришлось повозиться

**Tailwind.** `dashboard/postcss.config.cjs:3` подключает
`tailwindcss: {}` без пути к конфигу, а `content` в
`dashboard/tailwind.config.cjs:12` задан путями от текущего каталога.
Поэтому PostCSS задан в `main.ts` объектом: конфиг Tailwind берётся
у дашборда, его относительные пути разворачиваются в абсолютные,
и к `content` добавляется `showcase/stories` — иначе классы из историй
и из рамок не попадут в сборку.

**Vite root.** Vite отдаёт предсобранные зависимости по URL
`/.vite/deps`, а он считается от `root`. Если увести только `cacheDir`,
превью падает на `Failed to fetch dynamically imported module`.
Поэтому в `main.ts` уводится и `root`, и `cacheDir` — внутрь
`medusa-src/` при этом ничего не пишется.

**TooltipProvider.** Провайдер — отдельный именованный экспорт
(`ui/src/components/tooltip/tooltip.tsx:124`), а не `Tooltip.Provider`.
С точкой получаешь `Element type is invalid`.

## Истории

Восемь. Пометки на историях задаются через `parameters` и рисуются
декоратором в `.storybook/preview.tsx`.

| раздел | история | пометка |
|---|---|---|
| По контракту | Два действия — минимум по правилу 4.1 | разрыв 4.2 |
| По контракту | Пять действий — рекомендуемый потолок | — |
| По контракту | С опасным действием | разрыв 4.3 |
| По контракту | С disabled и подсказкой | разрыв 3 |
| Враждебные данные | Очень длинная метка | — |
| Враждебные данные | Метка в одно слово без пробелов | — |
| Запрещено контрактом | Ноль действий | нарушение 4.1 |
| Запрещено контрактом | Одно действие | нарушение 4.1 |

**Красная рамка «ЗАПРЕЩЕНО КОНТРАКТОМ»** — состояние, которое контракт
не допускает.
**Оранжевая рамка «РАЗРЫВ С КОНТРАКТОМ»** — контракт этого требует,
а компонент пока не умеет.

## Истории написаны на нынешнем API

Контракт, раздел 3, описывает плоский `actions` и признак `destructive`.
В коде их нет: компонент принимает `groups`, поля `destructive` в типе
`Action` не существует (`action-menu.tsx:9-35`).

Истории написаны на `groups` — на том, что работает сегодня. Разрыв
не прячется, а показывается оранжевыми рамками. Когда компонент
переведут на контрактный API, истории надо переписать, а рамки снять.

## Что витрина уже показала

Проверено прогоном в браузере 2026-09-01.

**Опасное действие ничем не выделено.** «Удалить» в меню выглядит
как «Редактировать»: тот же цвет текста, та же иконка по насыщенности.
Отличает его только рисунок иконки и слово. Это правило 4.3, которое
компонент не выполняет.

**Длинная метка не переносится.** Меню растягивается почти во всю
ширину окна — одна строка от края до края. У метки нет ни `break-words`,
ни `truncate` (`action-menu.tsx:92`, `:112`), ширину никто не ограничивает.

**Слово без пробелов ведёт себя так же** — меню шире, чем нужно,
перенос не происходит. Контракт длину и вид метки не ограничивает,
так что это не нарушение, а измеренное поведение.

## Границы

Витрина показывает компонент в изоляции. Она не проверяет, как он
выглядит в реальном экране: в заголовке секции, в строке таблицы,
в карточке. Для этого есть `ds-ops/dev/` — запуск админки целиком.
