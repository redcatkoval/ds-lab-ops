# ds-ops/tools/links — проверка ссылок корпуса

## Запуск

Из `ds-ops/`:

```
python3 tools/links/check.py
```

Зависимостей нет, только Python 3.

Коды возврата: `0` — все ссылки ведут в существующие файлы;
`1` — есть битые.

## Почему отдельно от линтера

Линтер стережёт **контракт**: каждое правило несёт в него якорь —
дословную цитату, — и при расхождении встаёт с кодом 2, ничего
не проверив. Область линтера — дерево дашборда, предмет — соответствие
вызовов записанному правилу.

Здесь ни того, ни другого. Ссылка не следует ни из какого правила,
якоря у неё быть не может, и контракта, с которым она могла бы
разойтись, не существует. Это проверка **целостности корпуса**:
ведёт ли ссылка туда, где что-то есть.

Отсюда три различия:

| | линтер контрактов | проверка ссылок |
|---|---|---|
| область | `medusa-src/.../dashboard/src` | `ds-ops/**/*.md` |
| предмет | вызовы против правила | ссылки против файлов на диске |
| коды | 0, 1, 2 — есть состояние «не проверял» | 0 и 1 — «не проверял» невозможно |
| долг | baseline: нарушение можно заморозить | долга нет: битая ссылка всегда дефект |

Свести их в один инструмент значило бы завести правилу, у которого
нет контракта, поддельный якорь — и потерять смысл кода 2, который
сейчас означает ровно одно: правило и контракт разошлись.

## Что проверяется

Ссылки markdown вида `[текст](путь)` во всех `.md` внутри `ds-ops/`,
кроме `node_modules`, `.git`, `storybook-static` и `.vite`.

Проверяется одно: существует ли файл по этому пути. Расширение неважно —
ссылка на `tools/lint/rules/action-menu.json` проверяется так же,
как на соседний вопрос.

**Не проверяются** и в счёт не идут: внешние ссылки (`http://`,
`https://`, `mailto:`) и якоря внутри страницы (`#раздел`). За ними
нет файла на диске. У ссылки вида `файл.md#якорь` проверяется файл,
якорь — нет.

**Ссылки внутри кода не считаются ссылками.** Содержимое обратных
кавычек и огороженных блоков гасится перед разбором: пример ссылки —
это показ, а не ссылка. Найдено на README этого же инструмента:
первая редакция сочла битой ссылкой строку, которой объясняла,
что такое ссылка.

## Откуда взялась

2026-09-08, при переводе Q-018 в решённые. Файл переехал в `reshennye/`,
ссылки **на** него поправили, а ссылки **из** него — нет: относительным
путям стало не хватать одного `../`. Тем же прогоном нашлись ещё две
такие же, оставшиеся от переезда Q-025 днём раньше и никем не замеченные.

Шесть битых ссылок в корпусе из 80 — и ни одна не мешала работе,
пока их не искали. Это и есть род дефекта, который ловится только
проверкой: он не падает, не краснеет и всплывает через месяц у того,
кто пошёл по ссылке.

## Проверки самого инструмента

Проведены 2026-09-08, каждая — прогоном.

1. **Находит несуществующий файл.** Временная запись со ссылкой
   на `DEC-999-net-takogo.md`: одна битая, код 1.
2. **Находит настоящий случай переезда.** В `Q-018` временно возвращены
   пути «до переезда» (`../decisions/` вместо `../../decisions/`):
   четыре битых, код 1. Файл восстановлен.
3. **Не ругается на внешние ссылки и якоря.** `https://`, `mailto:`,
   `#раздел` и `файл.md#якорь` — ноль битых, код 0.
4. **Проверяет не только `.md`.** Ссылка на несуществующий `.json`
   находится так же, как на несуществующий вопрос.
5. **Не считает ссылкой пример в коде.** Ссылки в обратных кавычках
   и в огороженном блоке пропускаются: ноль битых.
6. **Чисто на корпусе.** 80 ссылок, ноль битых, код 0.
