# Q-008. Номера строк в literals.json не ведут на реальный код

**Решён 2026-09-01.** См. «Чем закрыт» в конце.

**Был вопрос.** `literals.json` нумерует строки по файлу после вырезания
комментариев, а не по исходному файлу. Его номера на реальный код
не ведут.

**Что известно.** Пример: `p-4` в
`dashboard/src/components/authentication/route-permission-guard/route-permission-guard.tsx`
числится в `literals.json` на строке 118. Фактически лежит на строке 154.
На строке 118 исходного файла — вызов `useRegisterPermissions`, отступов
там нет.

Сдвиг не постоянный: он равен числу вырезанных строк выше по файлу,
поэтому в файлах без комментариев номера совпадают. В срезе
`routes/products/product-detail` все 32 записи совпали с исходными
номерами, в системном слое разошлись 124 записи из 215, в локальном —
178 из 495.

Значения при этом верны. Сверка по паре «файл + значение» между
`literals.json` и независимым обходом дала ноль расхождений на всех трёх
областях: 215/215, 495/495, 32/32
(`ds-ops/tokens/half-steps.json`, `method.калибровка`).
Расходятся только координаты.

`half-steps.json` нумерует по исходному файлу. Проверено на трёх
случаях:

- `routes/categories/category-detail/components/category-organize-section/category-organize-section.tsx:101` → `gap-x-0.5`
- `routes/translations/translation-list/components/translations-completion-section/translations-completion-section.tsx:95` → `mr-0.5`
- то же, `:234` → `mt-0.5`

**Кому адресован.** Нам. Чужого кода вопрос не касается — дефект в нашем
замере.

**Последствий не было.** Baseline на этих координатах не строился,
чинили до того, как на них что-либо построено.

**Чем закрыт.** Координаты всех 1726 вхождений в
`ds-ops/tokens/literals.json` пересчитаны на исходный файл. Метод описан
в самом файле, `method.нумерация_строк`. Прежний номер сохранён в поле
`line_prev`, остальные поля записей не менялись, `counts` не менялись.

Номер изменился у 789 вхождений в 65 файлах из 166, совпал у 937.
Сдвиг — от 0 до 40 строк.

Способ — монотонное выравнивание, без восстановления прежнего
вырезателя комментариев. Вырезание только удаляет строки и не меняет их
порядок, поэтому отображение «строка без комментариев → строка исходного
файла» строго возрастает, а сдвиг между ними не убывает. Вхождения
сгруппированы по паре «файл + прежний номер»; для каждой группы найдены
строки исходного файла, где присутствуют сразу все её значения; по всем
группам файла выбрано назначение, удовлетворяющее монотонности.
Назначение принималось только там, где такой путь ровно один. Путь
оказался единственным во всех 166 файлах.

**Чем доказано.** Три проверки.

1. Сплошная: значение каждой записи присутствует на назначенной ей
   строке исходного файла. 1726 из 1726, не подтвердилось — ноль.
2. Независимая: сверка с отдельным обходом исходников, который считает
   отступы сразу по исходным номерам строк — тем же, которым сделаны
   `half-steps.json` и `scale-full.json`. По ключу «файл + номер строки
   + значение» сверено 742 записи типа «отступ», расхождений ноль.
3. Контрольная выборка: 19 случаев из 19 разных файлов, все три слоя,
   все восемь типов значений. Подтверждены все 19; случаи выписаны
   в `method.нумерация_строк.проверка.контрольная_выборка`.

Случай из самого вопроса: `p-4` в `route-permission-guard.tsx`
числился на строке 118, теперь записан на 154 — там он и лежит.
